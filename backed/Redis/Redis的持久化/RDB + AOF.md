## Redis 混合持久化（RDB + AOF）

### 1. 为什么需要混合持久化？

RDB：

- 保存某个时间点的内存快照。
    
- 恢复速度快。
    
- 两次快照之间的数据可能丢失。
    

AOF：

- 记录 Redis 的写操作命令。
    
- 可以更及时地记录数据变化。
    
- 如果文件较大，恢复时需要执行大量命令，速度可能较慢。
    

因此，Redis 4.0 引入了混合持久化，将 RDB 和 AOF 结合起来。

### 2. 如何开启？

在 Redis 配置文件中设置：

```
aof-use-rdb-preamble yes
```

### 3. 混合持久化的工作流程

混合持久化主要在 AOF 重写过程中发挥作用：

1. Redis fork 创建子进程。
    
2. 子进程将 fork 时刻的全量内存数据以 RDB 格式写入新 AOF 文件的前半部分。
    
3. 主进程继续处理客户端请求，重写期间产生的增量写命令被记录下来。
    
4. 子进程完成 RDB 部分后，将增量写命令以 AOF 格式追加到文件后半部分。
    
5. 重写完成后，新文件替换旧的 AOF 文件。
    

### 4. 文件结构

混合持久化后的 AOF 文件由两部分组成：

- 前半部分：RDB 格式，保存 fork 时刻的全量数据。
    
- 后半部分：AOF 格式，保存 fork 之后产生的增量写命令。
    

恢复时：

1. 先加载 RDB 部分，快速恢复全量数据。
    
2. 再执行 AOF 部分的增量命令，恢复后续的数据变化。
    

### 5. 混合持久化的优点

1. 利用 RDB 的优势：快速恢复大量全量数据。
    
2. 利用 AOF 的优势：记录快照之后发生的写操作，减少数据丢失。
    
3. 避免恢复时逐条执行大量历史 AOF 命令，提高恢复效率。
    

注意：实际数据丢失情况还取决于 AOF 刷盘策略。

### 6. 核心总结

混合持久化 = RDB 全量数据 + AOF 增量命令。

**前半部分 RDB 负责快速恢复，后半部分 AOF 负责补充后续修改。**
