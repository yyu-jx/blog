
# 内存淘汰策略


当 Redis 的运行内存已经超过 Redis 设置的最大内存之后，则会使用**内存淘汰策略**删除符合条件的 key，以此来保障 Redis 高效的运行。
****
## Redis 内存淘汰策略有哪些？

Redis 内存淘汰策略共有八种，这八种策略大体分为「不进行数据淘汰」和「进行数据淘汰」两类策略。

1、==🔵不进行数据淘汰的策略==

noeviction（Redis3.0之后，默认的内存淘汰策略） ：它表示当运行内存超过最大设置内存时，不淘汰任何数据，这时如果有新的数据写入，会报错通知禁止写入，不淘汰任何数据，但是如果没用数据写入的话，只是单纯的查询或者删除操作的话，还是可以正常工作。

2、==🔵进行数据淘汰的策略==
针对「进行数据淘汰」这一类策略，又可以细分为「在设置了过期时间的数据中进行淘汰」和「在所有数据范围内进行淘汰」这两类策略。

在设置了==🟠过期时间的数据==中进行淘汰：
- **volatile-random**：随机淘汰设置了过期时间的任意键值；
- **volatile-ttl**：优先淘汰更早过期的键值。
- **volatile-lru**（Redis3.0 之前，默认的内存淘汰策略）：淘汰所有设置了过期时间的键值中，最久未使用的键值；
- **volatile-lfu**（Redis 4.0 后新增的内存淘汰策略）：淘汰所有设置了过期时间的键值中，最少使用的键值；

在所有==🟠数据范围内==进行淘汰：
- **allkeys-random**：随机淘汰任意键值;
- **allkeys-lru**：淘汰整个键值中最久未使用的键值；
- **allkeys-lfu**（Redis 4.0 后新增的内存淘汰策略）：淘汰整个键值中最少使用的键值。

****
## **Redis LRU 与 LFU 内存淘汰算法**

**1. LRU（最近最少使用）**

- 核心思想：淘汰最近最久没有被访问的数据。
    
- 传统实现：双向链表 + 哈希表。
    
- 存在问题：维护链表有额外内存开销，每次访问都需要移动节点。
    
- Redis 实现：近似 LRU。
    
- 实现方式：对象头 24 bit 的 lru 字段记录访问时间，通过随机采样选择最久未访问的 Key。
    
- 缺点：无法很好地解决缓存污染问题。
    

**2. LFU（最近最不常用）**

- Redis 4.0 引入。
    
- 核心思想：淘汰访问频次最低的数据。
    
- 优点：能够更好地保留真正的热点数据，缓解缓存污染问题。
    
- 实现方式：复用对象头的 24 bit lru 字段。
    

**3. LFU 字段划分**

- 高 16 bit：ldt，记录衰减时间信息。
    
- 低 8 bit：logc，记录访问频次估计值。
    
- 新 Key 的 logc 默认初始值为 5。
    

**4. LFU 两个核心机制**

- 衰减：距离上次衰减时间越长，logc 可能下降越多，让历史热点逐渐降温。
    
- 概率增长：logc 越大，增长概率越低，避免计数器过快增长。
    

**5. 两个重要配置**

- `lfu-decay-time`：控制衰减速度，越大衰减越慢。
    
- `lfu-log-factor`：控制增长难度，越大增长越慢。
****

**Redis 中的 LRU 和 LFU 有什么区别？为什么 Redis 4.0 引入 LFU？**

LRU 和 LFU 都是 Redis 的内存淘汰算法，但是两者的淘汰依据不同。

LRU 是最近最少使用算法，主要根据数据最近一次的访问时间进行淘汰，Redis 并没有使用传统的链表实现，而是采用近似 LRU 算法，通过对象头中的 24 bit 字段记录访问时间，并通过随机采样的方式选择最久未被访问的数据淘汰。

但是 LRU 存在缓存污染问题，例如批量查询大量只访问一次的冷数据，这些数据可能因为最近被访问而挤掉原本的热点数据。

因此 Redis 4.0 引入了 LFU 算法。LFU 根据数据的访问频次进行淘汰，更倾向于保留访问频率高的数据。

Redis 通过复用对象头中的 24 bit 字段实现 LFU，其中高 16 bit 存储 ldt 时间信息，低 8 bit 存储 logc 访问频次计数器。

同时，Redis 还引入了频次衰减和概率增长机制，让历史热点逐渐降温，并避免访问频次过快增长。
